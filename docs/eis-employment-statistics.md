# EIS 고용행정통계 활용 정책과 기술 조사

> 목적: EIS 고용행정통계의 **출처 표시, 허용된 개발 범위, 상용 운영 전 협의 조건, 수집 제약, 의미 분리, 기술 스파이크 범위**를 저장소에 고정한다.
> 본 문서는 고용노동부 국민신문고 공식 답변을 반영한 JBJ의 EIS 기준 문서다.

---

## 1. 출처와 이용 조건

- 공개된 EIS 통계는 별도 제한이 없는 경우 다운로드하여 이용할 수 있다.
- 출처는 정확히 **`고용노동부 고용행정통계`**로 표시한다.
- 공개 통계로 새로운 통계·분석을 만들 수 있다.
- 다만 JBJ가 계산한 결과는 고용노동부의 공식 통계로 오인되지 않도록 **JBJ 파생 결과**임을 명확히 표시한다.
- EIS 콘텐츠로 수익 또는 이에 준하는 이익을 얻는 서비스는 운영 전에 고용노동부와 별도 협의해야 한다. 협의 시 서비스 목적과 구체적인 활용 방식을 제출한다.

따라서 EIS의 상업적 이용이 절대 금지된 것은 아니다. **상용 프로덕션 출시는 사전 협의가 완료되어야 가능한 consultation-gated 상태**다.

문의처: 한국고용정보원 데이터지원팀 이장미 과장, 043-870-8553.

## 2. 현재 허용 범위와 출시 경계

### 지금 진행할 수 있는 작업

- EIS 통계표 구조, Open API, 다운로드 파일 조사
- 제한된 샘플 조회·다운로드

개발과 기술 검증은 진행할 수 있지만, 협의 완료 전에는 상용 출시를 준비 완료 상태로 표시하지 않는다.

## 3. Open API 일일 100회 제약

EIS Open API 호출 한도는 **일 100회**다. 짧은 시간에 같은 요청을 반복하거나, 조회 기간이 지나치게 넓거나, 조회 조건 조합이 과도하면 사전 통보 없이 차단될 수 있다.

100회는 단순 운영 주의사항이 아니라 collector의 **아키텍처 한도**로 취급한다. collector 설계 전에 다음을 먼저 조사한다.

1. 한 요청의 다기간 조회 가능 범위
2. 다직종·다지역 일괄 조회 또는 조건 묶음 지원 여부
3. API 대신 활용 가능한 다운로드 파일의 범위와 갱신 주기
4. 최신 공표분만 가져오는 증분 수집 방식
5. 재시도·캐시·중복 요청 방지와 일별 호출 예산 기록 방식

목표는 일 100회 이내에서 최신 데이터를 안정적으로 유지하는 것이다. `지역 × 직종 × 월 × 지표`를 각각 호출하는 brute-force 반복 수집은 설계안으로 채택하지 않는다.

## 4. 공식 통계와 JBJ 파생 결과

| 구분 | 표시·저장 원칙 |
|---|---|
| 공식/source | 출처를 **고용노동부 고용행정통계**로 표시하고 원천 값·단위·분류·공표 주기를 보존한다. |
| 파생/derived | JBJ 계산임을 API·문서·UI에서 명시하고 공식 통계와 별도 영역으로 제공한다. |

KOSIS 노동수요 API의 `metrics.official` / `metrics.derived` 분리 원칙과 같은 경계를 유지한다. JBJ 파생 결과의 제목·설명·화면 구성은 고용노동부가 작성·공표한 공식 통계처럼 보이지 않아야 한다.

## 5. KOSIS와의 의미 분리

EIS와 KOSIS에서 이름이 같은 지표라도 모집단, 행정 목적, 집계 방식, 분류 수준, 공표 주기가 다를 수 있다.

- 이름이 같다는 이유로 같은 사실로 병합하거나 합산하지 않는다.
- 각 데이터셋의 정의·단위·모집단·기간·직종 및 지역 분류를 조사한 뒤 비교 가능성을 판정한다.
- 의미가 다르면 기존 `fact_labor_demand`에 억지로 넣지 않고 EIS용 별도 Fact를 우선 검토한다.
- API·문서·UI에서 source와 산출 기준을 노출한다.
- 서로 비교할 수 없는 결측을 0으로 바꾸지 않는다.

## 6. 기술 스파이크

### 핵심 질문

> EIS가 **서울 × 소프트웨어 개발자 세부 수준**을 안정적으로 제공하는가?

KOSIS `DT_118N_DEN062`는 전국에서 KECO L1+L2+L3 **185개**, 지역에서 L1+L2 **45개**를 제공한다. 따라서 `서울 × 133 소프트웨어 개발자` 부재는 0이 아니라 원천 granularity 한계다.

### 후보 통계

- 구인·구직·알선·취업 현황
- 유효구인구직 현황
- 월별 피보험자 현황

### 확인할 차원과 지표

- 차원: 직종 소분류, 지역(시군구 가능 여부 포함), 월
- 지표: 구인인원, 구직인원, 취업인원, 피보험자수, 취득자수, 상실자수
- 메타데이터: 모집단, 집계 기준, 분류 버전, 단위, 수정·갱신 방식, API와 다운로드 파일의 일치 여부

성공 기준은 원하는 세부 조합을 일관된 코드와 정의로 조회할 수 있고, 100회 한도 안에서 증분 수집 가능한 경로를 확인하는 것이다. 성공한 뒤에만 EIS schema와 ETL을 확정한다.

## 7. Raw와 provenance

- API 응답과 다운로드 원본은 로컬 또는 데이터 볼륨에 보존한다.
- raw 데이터는 일반 Git에 커밋하지 않는다.
- `data_source`, 원본 파일명, SHA-256 checksum, 요청 파라미터, 수집 시각, 처리 건수, 오류를 `etl_run`과 함께 추적한다.
- 원천 정정이나 재수집 시 어떤 raw에서 어떤 결과가 만들어졌는지 재현 가능해야 한다.

## 8. 개발 순서

1. KOSIS 노동수요 마무리 — **완료**(수집 scope 검증 + missing≠0)
2. Canonical occupation mapping — **진행 중**(샘플 매핑 완료, 명명·매핑 정책·API 미완료)
3. EIS 기술 스파이크
4. 스파이크 성공 후 EIS schema / ETL
5. 임금 → 기타 고용 → NCS → Q-Net → 검색/상세/비교 UI
